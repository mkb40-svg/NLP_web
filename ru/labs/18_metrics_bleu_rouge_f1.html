Как это устроено

Метрики позволяют сравнивать системы автоматически, без экспертов. Все три метрики этой лаборатории считают совпадения ответа системы с эталоном (reference), который сделал человек.

BLEU (машинный перевод, тема 12) — это точность (precision) по n-граммам. Для n = 1..4 берём n-граммы перевода и проверяем, есть ли они в эталоне. Каждая n-грамма засчитывается не больше раз, чем встречается в эталоне (отсечение, clipping), иначе «мы мы мы мы» получил бы p₁ = 1.

pₙ = Σ min(count(g), max_ref count_ref(g)) / Σ count(g) BP = 1, если c > r; BP = exp(1 − r/c), если c ≤ r BLEU = BP · ⁴√(p₁ · p₂ · p₃ · p₄)

Точность не наказывает за пропущенные слова, поэтому добавлен штраф за краткость BP: c — длина перевода, r — длина эталона (при нескольких эталонах берётся ближайший по длине). Среднее геометрическое обнуляется, если хоть одна pₙ = 0, поэтому для отдельных предложений применяют сглаживание, а настоящий BLEU считают сразу по всему корпусу. Слабые места BLEU: он не знает синонимов и не видит, что «гуляли» и «гуляем» — формы одного слова. Для языков с богатой морфологией (русский, узбекский) полезен chrF: F-мера по символьным n-граммам.

ROUGE (реферирование, тема 13) смотрит прежде всего на полноту (recall): какая доля эталона попала в реферат. ROUGE-N считает общие n-граммы, ROUGE-L — длину наибольшей общей подпоследовательности (LCS): слова идут в том же порядке, но не обязательно подряд. LCS находится динамическим программированием, как расстояние Левенштейна (тема 11):

T[i][j] = T[i−1][j−1] + 1, если ref[i] = cand[j] T[i][j] = max(T[i−1][j], T[i][j−1]), иначе P = LCS / |cand|, R = LCS / |ref|

F1 (классификация и NER, темы 7 и 9) — гармоническое среднее точности и полноты:

P = TP / (TP + FP), R = TP / (TP + FN), F1 = 2·P·R / (P + R)

В NER единица счёта — сущность целиком. При точном сравнении (как в CoNLL) неверная граница даёт сразу FP и FN. Для нескольких классов F1 усредняют двумя способами:

  • micro: складываем TP, FP, FN всех классов и считаем одну F1; частые классы весят больше;
  • macro: считаем F1 каждого класса и берём среднее; редкий класс весит столько же, сколько частый.

Эксперименты

  1. Выберите «Синоним» и нажимайте «Шаг». Сколько n-грамм каждого порядка испортила одна замена слова? Почему потери растут с n? Затем выберите «Окончание» и сравните BLEU и chrF на правой панели.
  2. Выберите «Порядок слов». Почему p₁ = 1, а BLEU = 0? Включите по очереди «Второй эталон» и «Сглаживание»: что меняет каждая галочка?
  3. Выберите «Короткий» и проверьте BP по формуле exp(1 − 8/6). Допишите в поле два любых слова, которых нет в эталоне. Штраф исчез, но вырос ли BLEU?
  4. Выберите «Повторы» и выключите «Отсечение». Чему стала равна p₁? Почему BLEU всё равно равен 0?
  5. Во второй части выберите «Обратный порядок» и нажмите «Пуск». Почему ROUGE-1 = 1, а ROUGE-L всего 0,11? Сравните с «Длинным»: почему там R = 1, а P меньше?
  6. В третьей части для ORG выбрано «частично»: переключайте сравнение «точное» и «частичное». Почему при точном сравнении одна ошибка границы стоит и FP, и FN? Затем в четвёртой части выберите «Редкий класс» и нажмите на клетку «культура / культура», добавьте несколько верных ответов кнопкой +1. Какое среднее реагирует сильнее?
